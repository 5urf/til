## DTO(Data Transfer Object)는 무엇인가?

> 계층 간(Controller, Service, Repository 등) 데이터 교환을 위한 객체
> -
> 클라이언트의 요청 데이터를 전달받거나, 데이터베이스에서 조회한 데이터를 상위 계층으로 보낼때 사용되는 데이터의 '규격(스펙)'이다.
> -
> 주로 네트워크를 통해 전송되는 데이터의 형태와 규칙을 정의한다.

## DTO를 사용하는 이유는?
- 자동 유효성 검증(Validation): 파이프라인과 결합하여 컨트롤러 진입 전 필수 값 누락, 타입 오류등을 자동으로 걸러낸다.
- 코드 안정성 및 유지보수성: 필드 추가나 변경시 DTO 한곳만 수정하면 되며, 타입스크립트의 타입 추론 지원을 받는다.
- 데이터 캡슐화 및 보안: 클라이언트로부터 원치 않는 불필요하거나 악의적인 필드가 들어오는 것을 방지(화이트리스트 처리)한다.

## DTO를 Class로 정의하는 이유 (Interface vs Class)
- TypeScript의 `interface`는 컴파일 시점에 완전히 제거되어 런타임에 존재하지 않는다.
- 반면 ES6 `class`는 **런타임에도 실제 객체로 유지**된다.
- Nest.js는 런타임에 이 클래스 정보를 바탕으로 파이프(ValidationPipe)를 통해 **유효성 검사(class-validator)** 및 타입 변환(class-transformer)을 수행할 수 있다.

## Nest.js 데이터 흐름 속 DTO의 위치

```
[Client (HTTP Request)]
       │  (JSON Body 전송)
       ▼
┌──────────────────────────────────────────────┐
│  ValidationPipe                              │
│  - 요청 JSON을 CreateBoardDto 클래스로 변환  │
│  - 정의된 데코레이터(@IsNotEmpty 등) 검증     │
└──────────────────────┬───────────────────────┘
                       │ (검증 통과된 DTO 객체)
                       ▼
┌──────────────────────────────────────────────┐
│  Controller                                  │
│  - @Body() createBoardDto: CreateBoardDto    │
└──────────────────────┬───────────────────────┘
                       │ (DTO 전달)
                       ▼
┌──────────────────────────────────────────────┐
│  Service                                     │
│  - createBoard(createBoardDto) 로직 수행     │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
                 [DB / Entity]
```

- Client -> ValidationPipe: 클라이언트가 요청 본문(JSON)을 보내면, Nest.js의 파이프가 DTO 클래스 명세를 바탕으로 데이터를 검사하고 변환한다.
- Pipe -> Controller: 유효성 검사를 통과한 정제된 DTO 객체만이 컨트롤러 핸들러의 매개변수로 안전하게 전달된다.
- Controller -> Service: 컨트롤러는 가공되지 않은 요청 본문 대신, 타입이 보장된 DTO 객체를 그대로 서비스 계층에 넘겨 비즈니스 로직을 실행하도록 한다.
