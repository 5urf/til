>[!NOTE]
>모듈은 `@Module()` 데코레이터로 주석이 달린 클래스.
>
>`@Module()` 데코레이터는 Nest가 애플리케이션 구조를 구성하는 데 사용하는 메타데이터를 제공

![Modules](https://docs.nestjs.com/assets/Modules_1.png)

- 모든 Nest 애플리케이션에는 하나 이상의 모듈(루트 모듈)이 있다.
- 루트 모듈은 Nest가 애플리케이션 그래프를 구축하는 시작점 역할
- 모듈은 밀접하게 관련된 기능 집합으로 구성요소를 구성하는 효과적인 방법이며 적극 권장됨
- 같은 기능에 해당하는 것들은 하나의 모듈 폴더안에 넣어서 사용(ex: UserController, UserService, UserEntity 다 같은 기능이기에 UserModule안에 넣음)

![Shared modules](https://docs.nestjs.com/assets/Shared_Module_1.png)

- 모듈은 기본적으로 싱글톤(Singleton)이므로 여러 모듈간에 쉽게 공급자의 동일한 인스턴스를 공유할 수 있다

>[!NOTE]
싱글톤(Singleton)은 애플리케이션이 실행되는 동안 특정 클래스의 **인스턴스(객체)가 단 하나만 생성되도록 보장**하는 소프트웨어 디자인 패턴
>- 단일 객체 공유: 객체를 여러 번 호출하더라도 매번 새로운 객체를 생성하지 않고, 처음에 만들어둔 단 하나의 객체를 계속해서 반환하고 공유
>- 메모리 절약: 동일한 역할을 하는 객체를 중복해서 생성할 필요가 없으므로 시스템 메모리를 효율적으로 사용할 수 있음
>- 상태(State)및 자원 굥유: 애플리케이션 내의 여러 다른 클래스나 모듈에서 동일한 인스턴스에 접근하기 때문에, 데이터를 공유하거나 데이터베이스 연결같은 공통 자원을 관리하기에 적합

>이는 여러 모듈에서 같은 `Service`를 필요로 하더라도, Nest가 알아서 단 하나의 `Service`객체만 생성한 뒤 이를 요청한 모든 모듈에 동일하게 제공(주입)해 준다는 것을 의미.
>
>결과적으로 불필요한 메모리 낭비를 막고, 애플리케이션 전체에서 일관된 상태를 유지할 수 있게 해준다
